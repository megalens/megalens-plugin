# What the plugin needs from the engine CLI (engine-v2, not modified here)

1. **Engine installation.** With Node 20 or later, install the engine with `npm install -g megalens-review@0.1.3`. The plugin passes through the engine's `install` and `verify` commands for the pinned Codex CLI.
2. **A stable "still running" signal.** `result` on a running review exits 4 with the stderr text `review is still running`; `unknown review id` likewise. The plugin matches those strings. A distinct exit code, or `state` in a JSON body on stdout, would be sturdier.
3. **A refusal document.** A gateway refusal at prepare time exits 3 with stderr only and no findings file. The plugin renders that as "not completed". If the engine wrote a `status: failed, refused: true` document in that case too, the wording could name the cause (quota, spend cap, sign-in) without parsing stderr.
4. **Background-run hand-off.** `run --background` prints `{review_id, state}` on stdout. Confirm that the review id and state directory survive a Claude Code restart (the plugin assumes `status` and `result` work from any later session and any working directory).
5. **Per-tier timing.** Deep takes about 20 minutes; the plugin cannot show progress. A `status` field with passes done and elapsed minutes would help.
6. **macOS.** The engine refuses to run on macOS (no sandbox profile yet), so the commands report "failed to run" there.
7. **byo-login and byo-key.** Both disabled in the plugin (`BYO_LOGIN_ENABLED = false`, `BYO_KEY_ENABLED = false` in `scripts/lib/engine-core.mjs`, no env or flag switch; CONTRACT section 7). Turning one on means changing the constant in a reviewed release. Tests reach the byo-key path only through the `flags` argument of `main` / `chooseAuth`, which production code never passes. byo-login also needs design 02 test T26 on the real CLI.
9. **Env names.** The plugin passes the engine only `MEGALENS_STATE_DIR`, `MEGALENS_API_URL` and the token (gateway) or key (byo-key), plus basic variables (PATH, HOME, ...). If the engine needs another variable, say so here.
8. **Real-CLI check.** Nothing here was run against the real engine. The fake binary follows `src/cli.mjs`, the README and DEVIATIONS.md as read.

10. **Root.** The engine refuses to run as root unless `MEGALENS_ALLOW_ROOT=1`; the plugin deliberately does not pass that variable, so root shells fail closed (README says so).
11. **Exit 3 for BYO.** The plugin refuses the BYO modes itself, before the engine, so the engine's exit-3 BYO refusal is only a second line of defence here.
12. **GitHub App on-demand trigger, personal-repo installation lookup & repo-wide latest check lookup (backend, not modified here).** The MegaLens GitHub App (`src/lib/github-setup/flag.ts:20,53-54`, `src/lib/github-setup/webhook.ts:128,249-320`, `src/app/api/github-app/{callback,install,setup,start,webhook}/route.ts`) currently only handles `installation`, `installation_repositories`, `pull_request`, and default-branch `push` webhooks, and runs only the `standard` tier (`APP_REVIEW_TIER = 'standard'`); there is no on-demand review-start API endpoint or `check_suite.rerequested` handler. In addition, GitHub's `GET /repos/{owner}/{repo}/installation` requires a GitHub App JWT, `GET /orgs/{owner}/installations` requires org admin, `GET /user/installations` requires a GitHub App user token (`ghu_*`), and GitHub REST has no repo-wide `GET /repos/{owner}/{repo}/check-runs` endpoint (check runs can only be queried per commit ref `commits/{ref}/check-runs`). Personal repositories and non-admin organization members using a standard `gh` OAuth token need a MegaLens repo-status endpoint to verify an App installation without checks. The plugin keeps the App path disabled until the installation status and review start endpoints are available. A future repository review index could support status and result lookup across commits.
13. **Engine-native Local Standard background support.** Engine v2 (`src/tiers.mjs:8,15` and `src/cli.mjs:102,117-135`) provides native `--background` and persisted `status` and `result` for Deep. The plugin runs Standard in a detached worker, preserves the engine's normal gateway finalization, and saves the rendered result privately for later retrieval. Native Standard background support would let the engine own this lifecycle.
14. **`megalens-mcp setup codex` browser sign-in (external package `github.com/megalens/mcp`, not modified here).** In published `megalens-mcp@0.3.12`, `bin/codex-setup.mjs:740` calls `resolveEditorToken` (`bin/setup-shared.mjs:712`), which prompts `"Enter your MegaLens token"` instead of invoking `deviceLogin`, whereas the generic `npx megalens-mcp setup` command in the same package already runs browser device sign-in and writes `[mcp_servers.megalens]` into `~/.codex/config.toml` / `$CODEX_HOME/config.toml`. The Codex plugin docs and scripts now direct users to `npx megalens-mcp setup`; wiring `setup codex` itself to `deviceLogin` requires a release in `github.com/megalens/mcp`.
15. **No-copy GitHub Actions credential provisioning / GitHub App on-demand endpoints (backend / external CLI, not modified here).** While `APP_PATH_ENABLED = false` (`scripts/lib/gh-runner.mjs:20`), remote reviews require `.github/workflows/megalens-dispatch.yml` and the repository secret `MEGALENS_TOKEN` (`templates/megalens-dispatch.yml:40`, `scripts/lib/gh-runner.mjs:203`). Because `npx megalens-mcp setup` configures only the local Codex MCP entry (`~/.codex/config.toml`), a no-copy first run on a fresh GitHub repository remains blocked until either item #12 (GitHub App on-demand endpoints) ships or a supported no-copy GitHub secret provisioning flow is added to `megalens-mcp` / the MegaLens backend.
16. **Actions post-upload settlement / permanent artifact-upload failure refund (backend + `megalens/review-action` + `megalens-review`, not modified here).** In `megalens-dispatch.yml`, `megalens/review-action@950eb5f` (`mode: review`, running `megalens-review@0.1.3`) finalizes the review via `POST /api/v2/reviews/:id/complete` (`ws-post-launch/src/lib/engine-v2/service.ts:616`) *before* `actions/upload-artifact` uploads `findings.json`. `codex/runtime/templates/megalens-dispatch.yml` adds a retry step for transient artifact upload failures, and `runnerResult` fails loudly with `NOT COMPLETED` + run URL when no artifact exists. However, if `actions/upload-artifact` fails permanently, this client-only plugin repo cannot recover `findings.json` from the server (findings are not stored server-side) or release the settled charge / free claim; fixing permanent upload failure requires deferring server settlement until after artifact upload succeeds or adding an idempotent delivery-failure release endpoint in `ws-post-launch` and `megalens/review-action`.
