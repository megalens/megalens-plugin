# What the plugin needs from the engine CLI (engine-v2, not modified here)

1. **Engine installation.** With Node 20 or later, use the [pinned engine install command](docs/claude-code.md#local-engine-on-linux). The plugin passes through the engine's `install` and `verify` commands for the pinned Codex CLI.
2. **A stable "still running" signal.** `result` on a running review exits 4 with the stderr text `review is still running`; `unknown review id` likewise. The plugin matches those strings. A distinct exit code, or `state` in a JSON body on stdout, would be sturdier.
3. **A refusal document.** A gateway refusal at prepare time exits 3 with stderr only and no findings file. The plugin renders that as "not completed". If the engine wrote a `status: failed, refused: true` document in that case too, the wording could name the cause (quota, spend cap, sign-in) without parsing stderr.
4. **Background-run hand-off.** `run --background` prints `{review_id, state}` on stdout. Confirm that the review id and state directory survive a Claude Code restart (the plugin assumes `status` and `result` work from any later session and any working directory).
5. **Per-tier timing.** Deep takes about 20 minutes; the plugin cannot show progress. A `status` field with passes done and elapsed minutes would help.
6. **macOS.** The engine refuses to run on macOS (no sandbox profile yet), so the commands report "failed to run" there.
7. **byo-login and byo-key.** Both disabled in the plugin (`BYO_LOGIN_ENABLED = false`, `BYO_KEY_ENABLED = false` in `scripts/lib/engine-core.mjs`, no env or flag switch; CONTRACT section 7). Turning one on means changing the constant in a reviewed release. Tests reach the byo-key path only through the `flags` argument of `main` / `chooseAuth`, which production code never passes. byo-login also needs design 02 test T26 on the real CLI.
9. **Env names.** The plugin passes the engine only `MEGALENS_STATE_DIR`, `MEGALENS_API_URL` and the token (gateway) or key (byo-key), plus basic variables (PATH, HOME, ...). If the engine needs another variable, say so here.
8. **Real-CLI check.** Nothing here was run against the real engine. The fake binary follows `src/cli.mjs`, the README and DEVIATIONS.md as read.

10. **Root.** The engine refuses to run as root unless `MEGALENS_ALLOW_ROOT=1`; the plugin deliberately does not pass that variable, so root shells fail closed (README says so).
11. **Exit 3 for BYO.** The plugin refuses the BYO modes itself, before the engine, so the engine's exit-3 BYO refusal is only a second line of defence here.
12. **GitHub App on-demand endpoints (wired 23 Nov 2026; server settlement launch gate below).** The MegaLens server provides `GET /api/github-app/status`, `POST /api/github-app/review-now` (supporting `standard` and `deep`, PR or ref targets, and server-side job deduplication), and `GET /api/github-app/review-now/[id]` (with 24-hour findings retention). The plugin is wired to these endpoints with `APP_PATH_ENABLED = true`. A future repo-wide latest-job endpoint (and an optional operation idempotency key / expected `head_sha` on PR submissions) would let `/megalens:status` and `/megalens:result` discover App reviews started from another machine without a local bookmark and make lost PR replies safely recoverable.
13. **Engine-native Local Standard background support.** Engine v2 (`src/tiers.mjs:8,15` and `src/cli.mjs:102,117-135`) provides native `--background` and persisted `status` and `result` for Deep. The plugin runs Standard in a detached worker, preserves the engine's normal gateway finalization, and saves the rendered result privately for later retrieval. Native Standard background support would let the engine own this lifecycle.
14. **Server launch gate — deferred settlement for editor jobs with `ONE_PATH_V1` off (external server dependency).** In the MegaLens server (`src/lib/github-setup/on-demand.ts:169` and `src/lib/github-setup/worker-api.ts:374,408,435,599-614,714-738`), `editorReviewNow` admits editor jobs whenever `GITHUB_APP_V1=on` even if `ONE_PATH_V1` is off, while `prepare()` sets `defer_complete` from `isOnePathEnabled()` alone. When `ONE_PATH_V1` is off, `resultHandler` settles the wallet (`closeReview(..., 'complete')`) *before* GitHub publish and editor-result retention, so a permanent publish error marks the job `failed` (`publish_failed`) with no retained editor findings after credits or a free review have already been consumed. **Do not enable `GITHUB_APP_V1=on` / ship this plugin release until the server enforces deferred settlement for all editor jobs (including `shared`/reused jobs) regardless of `ONE_PATH_V1`, with server tests covering permanent publish failure when `ONE_PATH_V1` is off for both paid and free Standard admissions.**


15. **Codex preview sign in.** The Codex setup uses native browser OAuth via `codex mcp login megalens`. The source review found that the external `megalens-mcp` package at `0.3.12` prompts for a token with `setup codex` and can skip Codex when another editor is detected first.
16. **GitHub Actions setup on Codex.** The App runner in Codex stays off. Codex editor sign in and the GitHub Actions repository credential are separate. See [GitHub Actions setup](README.md#github-actions-setup) for the browser flow.
17. **Actions artifact delivery.** The dispatch workflow retries a failed upload under a second artifact name. Runners look for both artifacts on the same run and report missing findings as incomplete. The Codex source review recorded a settlement gap on permanent delivery failure. Closing it requires upstream Action and server work.
18. **Other host setup.** The checkout provides explicit preview entry points for GitHub Copilot, OpenCode and Antigravity. The source review tracked external npm setup parity in the [rollout notes](docs/more-hosts-later.md).
