2. **High — One request can trigger two billable reviews.** `scripts/hosts/text.mjs:87–90` first tells the host to avoid a second review, then explicitly tells it to make a follow-up call whenever it sees `needed_context`. The MCP service can include that field on an **approved, charged** result (`execution-plan-builder.ts:891,1058`), including the `result` of a terminal poll (`route.ts:3936`). Both tools used to start a review submit `megalens_debate` again on a follow-up. A new submission receives a fresh run ID and its own billing admission (`route.ts:3170–3185`, `async-pipeline.ts:746–756`). Test an approved result with missing context, a terminal halt and a lost response, and assert the expected submission, charge and shared free-counter behavior in each case. [MCP app route](/root/review-input/ws-app-credits/src/app/api/mcp/route.ts:3170) [Approved result builder](/root/review-input/ws-app-credits/src/lib/mcp-layer/execution-plan-builder.ts:1058) [Credit settlement](/root/review-input/ws-app-credits/src/lib/mcp-layer/async-pipeline.ts:746)

The instruction to skip secrets leaves filtering to the model. The established hosted command builds its payload with `scripts/collect.mjs`, which applies those checks, including when the final call is remote (`commands/megalens-review-remote.md:9–25`, `README.md:97`). Reuse the guarded collection path. For hosts without shell access, require a bounded, sanitized workspace change from a trusted tool or stop before uploading. Verify both paths with synthetic secret-bearing diffs and out-of-workspace files.

The current test injects its own callback and misses the CLI behavior (`tests/more-hosts.test.mjs:310–316`). [Device approval page](/root/review-input/ws-app-credits/src/app/device/page.tsx:103) [Published setup package](https://registry.npmjs.org/megalens-mcp/-/megalens-mcp-0.3.12.tgz)
